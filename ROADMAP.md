# PROJECT SPECIFICATION & AI-DLC EXECUTION ROADMAP
**Target Runtime:** Google Antigravity Agentic Workspace (Planning Mode + Subagent Execution)
**Domain:** Automotive Dealership Inter-Branch Delivery & Dynamic Payroll System (Jabodetabek Region)
**Primary Persona:** Branch Operations Supervisor (Web Portal)
**Core Architectural Constraint:** ZERO recurring third-party API subscription OpEx ($0/month external mapping/routing fees).

---

## 1. SYSTEM ARCHITECTURE & STACK CONSTRAINTS (NON-NEGOTIABLE)
Antigravity agents MUST adhere to the following deterministic stack to enforce $0 external API OpEx:
* **Routing Engine:** Self-hosted **OSRM (Open Source Routing Machine)** or **Valhalla** running inside Docker, initialized with the local Geofabrik Java Island OpenStreetMap extract (`java-latest.osm.pbf`).
* **Dual Routing Profiles:** Must compile two routing profiles (`car-toll` and `car-nontoll`) to accurately model Jabodetabek toll road vs. arterial road distances.
* **Map UI & Tiles:** **MapLibre GL JS** or **Leaflet** using free OpenStreetMap/Carto vector/raster tiles (no Mapbox/Google Maps API keys).
* **Backend API:** Python (**FastAPI**) or TypeScript (**Node.js / Express / NestJS**) with strict Pydantic/Zod schema validation.
* **Database:** **PostgreSQL + PostGIS** (Dockerized) for spatial shop coordinates, pre-computed Origin-Destination (OD) matrices, immutable delivery logs, and versioned payroll rate tables.
* **Frontend:** React + TypeScript + Tailwind CSS (responsive desktop-first UI for Supervisors).

---

## 2. WORKSPACE & ARTIFACT DIRECTORY CONTRACT
Before generating code, establish the following directory boundaries:
* `/infra` — `docker-compose.yml`, OSRM/Valhalla map preprocessing scripts, and database init SQL.
* `/backend` — API services, deterministic payroll calculation engine, OD matrix sync service, and unit/integration tests.
* `/frontend` — Supervisor web application (Delivery Logger, Shop/Rate Registry, Payroll Settlement & Export).
* `/artifacts` — Verification outputs generated by Antigravity (API test logs, database seed verification, Playwright browser recordings/screenshots).

## 3. AI-DLC EXECUTION ROADMAP (BOLT SEQUENCE)
Execute sequentially. **Do NOT proceed to Bolt $N+1$ until all Exit Criteria and Verification Gates for Bolt $N$ pass.**

### PHASE I: INCEPTION (Domain Modeling & Infrastructure Scaffolding)

#### Bolt 01: Domain Schema & Zero-OpEx Spatial Infrastructure
* **Objective:** Stand up the local PostgreSQL/PostGIS database and self-hosted OSRM/Valhalla routing container with Jabodetabek road data.
* **Tasks:**
  1. Generate `docker-compose.yml` orchestrating `postgres` (with `postgis`), `routing-engine` (OSRM/Valhalla), `backend`, and `frontend`.
  2. Write an automated shell script (`/infra/init-map.sh`) that downloads `java-latest.osm.pbf` (or a Jabodetabek bounding-box crop for rapid local dev/CI) and builds the routing graph files.
  3. Define database migrations for core entities:
     * `shops` (`id`, `code`, `name`, `city`, `address`, `geom` POINT(4326), `is_active`)
     * `drivers` (`id`, `employee_code`, `full_name`, `base_shop_id`, `base_fixed_salary`, `is_active`)
     * `od_distance_matrix` (`origin_shop_id`, `destination_shop_id`, `route_type` ENUM['toll','nontoll'], `distance_km`, `estimated_duration_min`, `route_polyline`, `updated_at`)
     * `rate_cards` (`id`, `name`, `effective_from`, `effective_to`, `min_km`, `max_km`, `rate_per_km`, `flat_trip_allowance`, `toll_reimbursement_flat`)
     * `delivery_logs` (`id`, `delivery_date`, `driver_id`, `vehicle_vin`, `vehicle_plate`, `origin_shop_id`, `destination_shop_id`, `custom_dest_geom`, `route_type`, `computed_distance_km`, `applied_rate_card_id`, `calculated_benefit_amount`, `supervisor_id`, `status` ENUM['pending','verified','voided'], `void_reason`, `created_at`)
* **Verification Gate (Exit Criteria):**
  * `docker-compose up` starts cleanly with zero external API keys configured.
  * Seed 12 realistic Jabodetabek dealership locations (e.g., Sunter, Kelapa Gading, Kebon Jeruk, Pondok Indah, Cawang, Cibubur, Depok Margonda, Bogor Pajajaran, Bekasi Barat, Cikarang, Tangerang BSD, Karawaci).
  * Automated script queries the local routing container for all $12 \times 12$ shop pairs and populates `od_distance_matrix` with non-zero road distances.

### PHASE II: CONSTRUCTION (Core Engines & Supervisor Interface)

#### Bolt 02: Routing Service & OD Matrix Pre-Computation Engine
* **Objective:** Build the backend spatial service that serves sub-10ms distance lookups for known inter-shop transfers and real-time local routing for ad-hoc delivery points.
* **Tasks:**
  1. Implement `POST /api/routes/calculate` accepting `{ origin_shop_id, destination_shop_id | custom_coords, route_type }`.
  2. Lookup logic: If both endpoints are registered shops, fetch directly from `od_distance_matrix`. If `custom_coords` is provided (e.g., direct-to-customer delivery), query local OSRM/Valhalla directly and return `distance_km` + GeoJSON polyline.
  3. Implement `POST /api/shops/recompute-matrix` triggered automatically whenever a shop is added or its coordinates are updated.
* **Verification Gate (Exit Criteria):**
  * Pytest/Jest suite verifies that Jakarta (Sunter) $\rightarrow$ Bogor (Pajajaran) returns realistic road distance (~55–65 km, NOT straight-line ~48 km).
  * Verify `toll` vs. `nontoll` toggles return distinct, accurate distances.

#### Bolt 03: Deterministic Compensation & Audit Ledger Engine
* **Objective:** Implement the dynamic salary/benefit calculation engine with immutable snapshots and audit compliance.
* **Tasks:**
  1. Build a pure, deterministic calculation module (`PayrollCalculator`) that evaluates `computed_distance_km` + `route_type` + `delivery_date` against active `rate_cards` (supporting tiered per-km rates + trip allowances).
  2. Implement `POST /api/deliveries` (Supervisor Log Entry):
     * Validates no duplicate `vehicle_vin` transfer overlap for the same driver/timestamp.
     * Snapshots `computed_distance_km`, `applied_rate_card_id`, and `calculated_benefit_amount` onto the `delivery_logs` row at creation time (preventing future rate edits from corrupting historical payouts).
  3. Implement `PATCH /api/deliveries/{id}/void` requiring a mandatory `void_reason` (never hard-delete financial records).
* **Verification Gate (Exit Criteria):**
  * Unit tests covering boundary conditions: `0 km` (same-shop error), tier boundaries (`15.0 km` vs `15.01 km`), rate-card effective date transitions, and voiding workflows.

#### Bolt 04: Supervisor Progressive Web App (PWA) & Offline Sync Queue
* **Objective:** Build an installable, offline-capable Responsive Web App / PWA adhering to MDN and Microsoft Edge PWA best practices, styled with self-hosted **Inter** typography.
* **Tasks:**
  1. **Typography & Design Setup:**
     * Install `@fontsource-variable/inter` and configure Tailwind CSS with `Inter` as default sans font and `tabular-nums` utility enforcement on all financial/distance readouts.
  2. **PWA Core & Service Worker (`vite-plugin-pwa`):**
     * Configure `manifest.webmanifest` (standalone display, maskable icons, wide/narrow screenshots, Jabodetabek Dealership Fleet branding).
     * Configure Workbox caching: precache app shell + local Inter fonts; `StaleWhileRevalidate` for `/api/shops`, `/api/drivers`, and `/api/od-matrix`.
     * Build an IndexedDB offline queue (`useOfflineDeliveryQueue`) that captures `POST /api/deliveries` when `navigator.onLine === false`, displays a `"Queued Offline"` status pill, and automatically replays requests when connectivity returns.
     * Add a custom **"Install App"** button in the header triggered by `beforeinstallprompt` and an update banner when a new Service Worker activates.
  3. **Supervisor Views (Responsive Desktop + Mobile):**
     * **Quick Delivery Logger:** 3-click selection (`Driver` $\rightarrow$ `Origin Shop` $\rightarrow$ `Destination Shop` + `Toll/Non-Toll` toggle) with instant distance (`km`), IDR benefit preview, and **MapLibre GL / Leaflet** route polyline map. Includes Ad-Hoc map pin mode.
     * **Daily Delivery Ledger:** Searchable/filterable audit table with void/correction modal (no `window.confirm`).
     * **Shop & Rate Registry:** Branch coordinate manager and IDR tiered rate editor.
* **Verification Gate (Exit Criteria):**
  * Lighthouse / DevTools PWA audit checks pass: valid manifest, active Service Worker, offline start_url response (`200 OK`).
  * Browser Subagent test: Simulate offline mode $\rightarrow$ log a delivery between two branches using cached OD matrix $\rightarrow$ verify record persists in offline queue $\rightarrow$ restore network $\rightarrow$ verify automatic sync to PostgreSQL.

#### Bolt 05: Payroll Aggregation, Anomaly Flagging & Export Module
* **Objective:** Enable Supervisors and Finance/HR to process accumulated delivery logs into payout summaries.
* **Tasks:**
  1. Implement `GET /api/payroll/summary?start_date=YYYY-MM-DD&end_date=YYYY-MM-DD&shop_id=...` aggregating per-driver:
     * `total_trips`, `total_distance_km`, `base_fixed_salary`, `total_variable_benefit`, `total_payout`.
  2. **Deterministic Anomaly Flags:** Flag records for supervisor review if:
     * Driver cumulative daily distance exceeds `300 km` in Jabodetabek.
     * Same `vehicle_vin` is logged twice within `60 minutes`.
  3. **Export Engine:** Generate formatted `.xlsx` and `.csv` payroll settlement sheets with summary tabs and itemized trip audit tabs.
* **Verification Gate (Exit Criteria):**
  * End-to-end integration test seeds 100 multi-driver deliveries over a 30-day window, executes payroll aggregation, verifies mathematical parity between itemized logs and summary totals, and validates generated `.xlsx` file readability.
